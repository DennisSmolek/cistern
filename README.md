## Cistern

Geometry toolkit for round galleries. Monorepo managed with pnpm workspaces, Vite, tsup, Changesets, TypeDoc, and VitePress.

## Requirements

- Node >= 20.11
- pnpm >= 10

## Install

```bash
pnpm install
```

## Workspace layout

- apps
    - docs: VitePress site. API docs generated by TypeDoc into `apps/docs/api`.
    - studio: Playground app using packages.
    - starter, examples: Minimal consumer apps.
- packages
    - core, camera, r3f: Publishable packages built with tsup.
    - types: Global ambient types consumed by packages/apps.

## Common scripts (run from repo root)

- Dev all core packages + studio app (watch):

```bash
pnpm dev
```

- Dev only the studio:

```bash
pnpm dev:studio
```

- Dev examples or starter app:

```bash
pnpm dev:examples
pnpm dev:starter
```

- Build everything (all packages/apps that define build scripts):

```bash
pnpm build
```

- Lint and format:

```bash
pnpm lint
pnpm format
```

## Release flow (Changesets => npm)

- Create a feature branch and make your changes.
- Add a changeset (select affected packages and bump type):

```bash
pnpm changeset
```

- Commit and push your branch, open a PR. The changeset file lives under `.changeset/`.
- Merge to `main` when approved.
- On push to `main`, the Release workflow runs. It will:
    - Install deps and build all packages.
    - If there are unpublished changesets on `main`, it will:
        - Run `pnpm release:version` (applies versions, updates changelogs, syncs lockfile)
        - Run `pnpm release:publish` (builds and publishes affected packages to npm)
    - If there are no changesets, it no-ops (no npm publish).

Notes:

- Publishing requires `NPM_TOKEN` (npm Automation token) in repo secrets.
- Scoped publishing is configured for `@cistern/*` with provenance enabled.

## Docs deployment (Cloudflare Workers)

- Docs deploy workflow only runs when files under `apps/docs-astro/**` change (or the workflow file changes).
- It builds workspace packages, builds the docs app, then deploys with Wrangler using `apps/docs-astro/wrangler.toml`.
- The Worker is bound to your domain via a Route in Cloudflare.

## Documentation

There are two kinds of docs:

1. Narrative docs (Markdown): live under `apps/docs/*.md` (VitePress). Start a local docs server:

```bash
pnpm dev:docs
```

2. API reference (generated): produced by TypeDoc into `apps/docs/api`.

### Authoring docs

- Write guides/pages in `apps/docs` (e.g. `index.md`, additional `*.md`).
- Update navigation/sidebar in `apps/docs/.vitepress/config.ts`.
- Add rich TSDoc comments directly to exported APIs in packages; TypeDoc pulls these.

Example TSDoc (in any exported symbol file):

```ts
/**
 * Computes points along a circular gallery path.
 * @param radius - Outer radius in meters.
 * @param segments - Number of segments; higher is smoother.
 * @returns Ordered list of points on the path.
 */
export function generatePath(radius: number, segments = 64) {
    /* ... */
}
```

### Build docs

- Generate API docs (TypeDoc → `apps/docs/api`):

```bash
pnpm --filter @cistern/docs run build:api
```

- Build the VitePress site (output → `apps/docs/.vitepress/dist`):

```bash
pnpm --filter @cistern/docs run build
```

You can run those back-to-back whenever APIs change.

### Where TypeDoc looks

Top-level `typedoc.json` currently documents `@cistern/core`:

```json
{
    "entryPoints": ["packages/core/src/index.ts"],
    "out": "apps/docs/api",
    "tsconfig": "packages/core/tsconfig.json"
}
```

To include more packages, list additional entry points (and ensure those packages export the APIs you want documented):

```json
{
    "entryPoints": [
        "packages/core/src/index.ts",
        "packages/camera/src/index.ts",
        "packages/r3f/src/index.ts"
    ],
    "out": "apps/docs/api"
}
```

Also add links in `apps/docs/.vitepress/config.ts` to the generated module pages (e.g. `/api/modules` opens the index for all entry points).

### Deploy docs

The built site lives in `apps/docs/.vitepress/dist`. Deploy using any static host:

- Vercel: set the project root to `apps/docs`, and the build command to `pnpm i && pnpm --filter @cistern/docs run build:api && pnpm --filter @cistern/docs run build`. Output dir: `.vitepress/dist`.
- Netlify: Base `apps/docs`, same build command as above, publish directory `.vitepress/dist`.
- GitHub Pages: build locally and push the contents of `apps/docs/.vitepress/dist` to a `gh-pages` branch, or use a GitHub Action for VitePress.

## Conventions

- Prefer adding/maintaining types in `packages/types` as ambient declarations, and keep package public APIs clean and exported for TypeDoc.
- Follow existing formatting; keep code readable and well-commented (use TSDoc for exported APIs).
